# tevm-run API reference

`tevm-run` is normally used as a binary, but the pieces it is built from are exported so
you can embed the runner in a build script or a test harness.

```ts
import { argsSchema, configPath, parseArgs, resolveConfigPath, run, runArgs } from 'tevm-run'
```

All exports are documented with JSDoc in
[`packages/tevm-run/src`](https://github.com/evmts/tevm-cli/tree/main/packages/tevm-run/src).

## `run`

```ts
function run(positionals?: string[]): Promise<import('bun').$.ShellOutput>
```

Execute a script with Bun using the `tevm-run` bunfig, which preloads the Tevm Solidity
plugin so the script can `import` `.sol` files directly.

The script's stdout and stderr stream to the calling process. `run` logs one line,
`[tevm-run] <scriptPath>`. It never logs forwarded arguments, because they can carry
secrets such as RPC URLs or private keys. On a non-zero exit, the captured output is echoed
before throwing, so failures stay readable in CI logs.

**Parameters**

| Name | Type | Description |
| --- | --- | --- |
| `positionals` | `string[]` | `[scriptPath, ...scriptArgs]`. Defaults to the positionals parsed out of `process.argv`, which is what the `tevm-run` binary passes. |

**Returns** — `Promise<ShellOutput>`, the completed Bun shell result.

**Throws** — `Error('No script path provided.')` if `positionals` is empty. `Error` if the script exits non-zero. The underlying Bun shell error is
attached as `cause`, so `err.cause.exitCode`, `err.cause.stdout`, and `err.cause.stderr`
are available.

```ts
import { run } from 'tevm-run'

try {
	await run(['./scripts/deploy.ts', '--network', 'optimism'])
	console.log('deploy script finished')
} catch (error) {
	const cause = (error as { cause?: { exitCode?: number } }).cause
	console.error(`deploy script failed with code ${cause?.exitCode ?? 'unknown'}`)
	process.exit(1)
}
```

## `parseArgs`

```ts
function parseArgs(rawArgs: string[]): { values: Record<string, never>; positionals: string[] }
```

Split a raw `process.argv` into the script path and the arguments forwarded to it.

- Everything up to and including the `tevm-run` entry point (a bare `tevm-run` or a path
  ending in `/tevm-run` or `/tevm-run.js`) is stripped. Without an entry point, the first two
  entries are stripped, like `process.argv`.
- Everything after the script path is forwarded verbatim, including `--flags`, `-v`, and
  `--`.
- A leading `--` before the script path is dropped, so `tevm-run -- ./script.ts` works.

**Throws** — `Error('No script path provided.')` if no script path follows `tevm-run` (it
also prints the usage line to stderr); `TypeError` if a `--flag` appears *before* the script
path, because `tevm-run` has no flags of its own and [`argsSchema`](#argsschema) is strict.

```ts
import { parseArgs } from 'tevm-run'

const { positionals } = parseArgs(['/bin/bun', '/usr/local/bin/tevm-run', './script.ts', '--network', 'optimism'])
console.log(positionals)
// [ './script.ts', '--network', 'optimism' ]
```

## `runArgs`

```ts
function runArgs(scriptPath: string, positionals: ReadonlyArray<string>): string[]
```

Build the argument list `run` passes to `bun`. Use it to spawn Bun yourself with the same
config `tevm-run` uses.

```ts
import { runArgs } from 'tevm-run'

runArgs('./script.ts', ['--network', 'optimism'])
// ['run', '--config=/tmp/tevm-run-XXXX/bunfig.toml', '--install=fallback', './script.ts', '--network', 'optimism']
```

## `resolveConfigPath`

```ts
function resolveConfigPath(): string
```

Return the path of a generated `bunfig.toml` whose `preload` points at the absolute path of
`plugins.js`. Bun resolves a relative `preload` against the working directory, so the
packaged `bunfig.toml` only works from inside the package; this one works from any
directory. The file is written to a temp directory once per process and reused.

**Throws** — `Error` if the temp directory is not writable.

## `configPath`

```ts
const configPath: string
```

Absolute path to the `bunfig.toml` shipped inside the package. Its `preload` entry is
relative, so it only works when Bun runs from the package directory. To invoke Bun yourself
with the Tevm plugin preload, use [`resolveConfigPath`](#resolveconfigpath):

```ts
import { resolveConfigPath } from 'tevm-run'
import { $ } from 'bun'

await $`bun test --config=${resolveConfigPath()}`
```

## `argsSchema`

```ts
const argsSchema: { options: Record<string, never>; strict: true; allowPositionals: true }
```

The schema handed to `node:util`'s `parseArgs`. `tevm-run` has no flags of its own, so it
declares no options, allows positionals, and stays strict.

```ts
import { parseArgs } from 'node:util'
import { argsSchema } from 'tevm-run'

const args = parseArgs({ ...argsSchema, args: ['bun', 'tevm-run', './script.ts', 'alice'] })
console.log(args.positionals)
// [ 'bun', 'tevm-run', './script.ts', 'alice' ]
```

Note the difference from `tevm-run`'s own `parseArgs`: the raw `node:util` call keeps the
leading `bun` and `tevm-run` entries, while `tevm-run`'s wrapper strips them.

## Composing them

```ts
import { parseArgs, run } from 'tevm-run'

const { positionals } = parseArgs(process.argv)
await run(positionals)
```

That is, in full, what the `tevm-run` binary does.
